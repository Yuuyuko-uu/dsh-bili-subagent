# 命令行扫码登录（`bin/qr.mjs`）

不开 DSH 界面，直接在终端里出一张能扫的 B站 登录码：终端画码 + 唯一文件名 PNG + 过期自动换新 + 扫完自动写凭证。

## 为什么单独做一个

走设置页 / 聊天工具出码有两个实际麻烦：

1. PNG 每次写到**同一个文件名**（`bili-duty/qrcode_login.png`），聊天窗口、看图器容易显示缓存下来的旧图；
   实测三次扫到的都是旧码，`poll` 一直 `86101`（未扫码）。
2. 码只有约 **180 秒**有效期，等你看到消息、再拿手机去扫，往往已经快过期。

这个程序把这两点都绕开：**终端里直接画码**（不经过任何图片缓存）、**文件名带唯一后缀**、**过期自动换一张新的**。

## 用法

双击 `bin\二维码登录.cmd`，或者在仓库目录里：

```bash
node bin/qr.mjs                  # 出码 + 轮询 + 过期自动换新（默认跑 15 分钟）
node bin/qr.mjs --dry            # 只出一张码就退出（自检用）
node bin/qr.mjs --once           # 只出一次，过期就退出
node bin/qr.mjs --no-open        # 不弹系统看图器
node bin/qr.mjs --no-ascii       # 终端里不画二维码
node bin/qr.mjs --timeout 300    # 总共跑 300 秒
node bin/qr.mjs --out D:\qrimg   # PNG 放哪儿
```

跑起来之后它做这几件事：

- 立刻在控制台画出二维码（手机 B站 → 我的 → 扫一扫，直接扫屏幕）
- 同时存一张文件名唯一的 PNG 到 `%TEMP%\bili-qr\`，并调系统看图器打开
- 每 0.8 秒查一次状态；码过期就自动出新的
- 扫上并确认后，把凭证写进 `%USERPROFILE%\.dsh\bili-duty\bili_credential.json`（插件认的那四个字段）
- 默认最多跑 15 分钟，超时自己退出

## 实现要点

只加了 `bin/qr.mjs` 一个文件，**复用插件自己的 `lib/login.mjs`**（`loginStart` / `loginPoll` / `saveCredential`），
所以登录逻辑和插件里那套完全一致，没有第二份实现：

- 出码：`GET passport.bilibili.com/x/passport-login/web/qrcode/generate`
- 轮询：`86101` 未扫 / `86090` 已扫待确认 / `0` 成功 / `86038` 过期
- 凭证：从轮询响应的 `Set-Cookie` 里抠 `SESSDATA` / `bili_jct` / `DedeUserID` / `buvid3`（缺的用 `finger/spi` 补）
- 画码：用插件 venv 里的 Python `qrcode`（`print_ascii()` 出终端码，`make_image()` 出 PNG）

### 两个踩过的坑（都已修）

1. **轮询太慢会错过唯一一次「成功」**。B站 在确认后只会在**下一次轮询**回一次 `code = 0`，
   之后同一个 key 立刻变 `86038`。1.5 秒一轮时容易只看到「已扫码 → 已失效」，表现成「扫了没反应」。
   现在固定 **800 ms** 一轮，并且把「扫过但没确认」和「没人扫」分开提示。
2. **写凭证失败不能当没事**。在沙箱 / 加固环境里写 `%USERPROFILE%\.dsh` 可能报 `EPERM`，
   而这时登录其实已经成功了。现在捕获该异常，打印明确提示，并把凭证**备份到 PNG 同目录**
   （`%TEMP%\bili-qr\bili_credential.json`），提示你复制回哪里。

### 子进程为什么不走管道

Python 的 stdout/stderr 重定向到临时文件再读回。
沙箱（以及部分加固环境）禁止开命名管道，用 `pipe` 会直接 `spawn EPERM`。

## 注意

- 需要先点过设置页的「装主依赖」（venv 里有 `qrcode`）。
- 它只写插件家目录下的凭证文件，不碰插件包目录。
- Windows 上给了 `bin\二维码登录.cmd` 双击入口；其他平台直接 `node bin/qr.mjs`。
