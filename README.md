# dsh-bili-subagent ｜ 刷 B站（子代理版）

> **让你的 AI 伙伴自己去刷 B站，然后回来跟你说话。**
>
> 插件不再自己"跑一轮然后写一份日报给你看"——它只负责**派一个子代理去看**，
> 子代理读字幕、翻评论、挑出值得的，写一份**给伙伴看的内部报告**；
> 再由你的伙伴（你自己的 AI）**用自己的口吻**决定怎么告诉你：公开评论只写一两句勾人，私信可以详细。

> **本仓库是 [c1overzz/dsh-bili-scroll](https://github.com/c1overzz/dsh-bili-scroll) 的改版（fork）**，
> 基于它的 `0.1.10`，沿用 MIT 许可并保留原作者署名与 LICENSE。感谢原作者把底子打好。

## 它现在怎么干活

```
到点（或你点「现在跑一轮」）
   ↓
插件往「你指定的那个会话」里塞一句（文案可在设置页改）：到谷时啦，去 B 站刷一轮吧～
   ↓
你的伙伴看到这句 → 调 bili_scan → 插件派出一个子代理
   ↓
子代理只负责「看」：搜视频 → 扫标题 → 看简介 → 读整段字幕 → 翻评论区
   ↓
交回一份内部报告（标题 / BV号 / 讲了什么 / 为什么值得 / 评论区反响）
   ↓
伙伴按设置决定怎么告诉你：评论 @ 你 ／ 私信你 ／ 两个都发
```

报告同时追加写入 `<DSH_HOME>/bili-duty/out/<日期>.md`，想回看随时能翻。

## 本版加了什么（相对上游）

- ⭐ **派子代理去刷**：刷站的不再是插件，而是你的伙伴派出去的一个子代理 —— 看和说彻底分开
- ⭐ **挑什么样的（两道硬门槛）**：最低播放量、至少发布几天。不达标的视频在**搜索那一步就被滤掉**，
  子代理根本看不到；有门槛时会自动多抓几倍再筛，免得筛完一条不剩
- ⭐ **投递方式自己选**：评论 @ ／ 私信 ／ 两个都发；两者都开时，**这一轮没发评论就发不出私信**
- ⭐ **自动刷在哪个会话**：到点只往你选的那个会话说一句，能看着它干活、也能接着追问
- **子代理的模型可换**：provider + 模型联动下拉，指到免费中转就不花官方额度
- **提示词全在面板里改**：称呼 + 子代理流程，支持 `{owner}` `{direction}` `{n}` 占位符，改完不用重启
- **额度口径明确**：`每天最多自动刷几轮`，面板显示「今天已自动刷 X / N 轮」—— **手动跑不占额度**
- **13 个工具**：`bili_scan`（主入口）`bili_search` `bili_subtitle` `bili_comments` `bili_reply`
  `bili_send_message` `bili_send_dynamic` `bili_status` `bili_config` `bili_whoami` `bili_login_start` `bili_login_poll` `bili_setup`
- **删掉的**：本地转写（约 1 GB）、headless/overlay、工作区、关注关键词、上游的群答疑与 `tools/` 开发脚本
- **修掉的**：DSH 原生设置下「改了又弹回去」、`/config` 白名单丢字段、`pythonPath` 落成 `python` 导致二维码画不出

## 自动刷是怎么触发的

编排器每 **60 秒**看一次表，几件事**同时成立**才跑：

1. **自动刷时段**不是「只手动」（三档：只手动 / 只在谷时 / 全天都跑）
2. 今天自动刷的轮数 **< 每天最多自动刷几轮**
3. 「只在谷时」时，现在得落在某个窗口里：中午 **12:00–14:00** 或 夜间 **18:00–09:00**；**整个周末整天都算谷时**（「全天都跑」不看这条）
4. 离上一轮已经隔够 **两轮之间至少隔几分钟**（默认 180 分钟 = 3 小时）

举例：设「每天 5 轮」「间隔 180 分钟」，晚上那一轮会这样走 ——

```
18:00 → 21:00 → 00:00 → 03:00 → 06:00   （5 轮用完就停）
```

想跑得密（比如周末狂刷）：把间隔调到 **5 分钟**、每天轮数调到 50 —— 一分钟一跳的表照样能一轮接一轮地来。

⚠️ **没投出去不算数**：目标会话没醒着、或者派子代理失败，这一轮的额度会**退回去**，下一个周期还能重试。

## 适配哪个 DSH 版本（不用操心）

这个插件**跟着 DSH 一起更新**：作者这边跑的就是最新版的 DSH，**最新版插件永远是给最新版 DSH 写的**。

所以看到「不适配 / 不支持」之类的提示，基本都是**装到了旧版本** —— 升级到最新版、重启一次 DSH 就好。
真遇到新版对不上（比如 DSH 刚升级、插件还没跟上），提个 issue，作者会跟着改。

当前实测对照：插件 **0.8.5** ↔ DSH **0.2.1-rc.3**（2026-10-26）

## 装之前（一条前提，30 秒）

机器上要有 **`Python 3.10+`** 或 **`uv`** —— 有一个就够：

- 有 `uv` 最好：单文件、解压就能用、不用管理员、不用进 PATH；
- 都没有也没关系：点「装主依赖」时插件会**自己下一份 `uv`** 到自己的家目录（免管理员），
  先直连 GitHub，不通走国内加速，下载完核对官方 `sha256`；
- ⚠️ 杀软报这个下载：把 `%USERPROFILE%\.dsh\bili-duty\bin\` 加白；
  不想加白就自己装一份 `uv` 或 Python 3.10+。

需要 **DSH ≥ `0.1.7-rc.1`**。版本不满足时内核会**静默跳过**这个插件（装了跟没装一样，不报错）。

### 装完起不来？先看这个

如果 DSH 弹「The application could not start」，错误里有 `Unexpected token '﻿'`、`is not valid JSON`、
`readProfileManifest` —— 那是 profile 的 `package.json` 被存成了 **UTF-8 带 BOM**。
**跟插件无关**：内容都是对的，只是开头多了三个看不见的字节，DSH 读它就崩。

**先找出来**（不同装法位置不一样，别猜 —— 真正的 profile 目录里同时有 `cordis.yml`、`cordis.patch.yml`、`package.json`；机器上别处那些同名的都不算）：

```powershell
Get-ChildItem C:\,D:\,E:\ -Directory -Filter profiles -Recurse -Depth 4 -ErrorAction SilentlyContinue |
  ForEach-Object {
    Get-ChildItem $_.FullName -Directory -ErrorAction SilentlyContinue | ForEach-Object {
      $p = Join-Path $_.FullName 'package.json'
      if ((Test-Path (Join-Path $_.FullName 'cordis.patch.yml')) -and (Test-Path $p)) {
        $b = [System.IO.File]::ReadAllBytes($p)
        $bom = ($b.Length -ge 3 -and $b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF)
        "{0}   BOM={1}" -f $p, $bom
      }
    }
  }
```

**输出里 `BOM=True` 的那一行，就是要修的文件**（标准安装在 `C:\Users\<你>\.dsh\profiles\<档名>\package.json`）。
去掉 BOM（路径换成上面那一行）：

```powershell
$p = "把上面 BOM=True 那一行的路径粘到这里"
[System.IO.File]::WriteAllText($p, [System.IO.File]::ReadAllText($p), (New-Object System.Text.UTF8Encoding($false)))
```

然后重启 DSH 就好，**数据一点没丢**。实在进不去时，那个错误框里的
**「Disable third-party plugins, back up profile patch, and restart」** 能先起来，再一个个开回去定位。

> ⚠️ 手动改 profile 里的文件，一律存 **UTF-8 无 BOM**。让 AI 帮你改时，别让它用
> `Set-Content -Encoding UTF8` 或 `Out-File -Encoding utf8`（Windows 自带的这两个默认**带 BOM**）。

## 更新到最新版

**最省事**：把这个仓库的地址丢给你自己的 DSH，说「**帮我更新这个插件**」。装完**重启一次 DSH**。

也可以点 **设置 → 刷B站 最上面的「检查更新」** —— 有新版会提示，还能一键复制更新命令。

命令行（`--profile` 照你平时那个写，桌面端一般 `desktop`、网页端 `web`）：

```bash
dsh plugin --profile desktop remove dsh-bili-subagent
dsh plugin --profile desktop add github:Yuuyuko-uu/dsh-bili-subagent
```

> ⚠️ **必须先卸再装**：直接装可能拿到缓存里的旧副本，装完还是老的。
> ⚠️ 装完**重启一次 DSH**才会用新代码。

### 我的设置会不会丢？

**不会。** 设置存在 DSH 家目录（`%USERPROFILE%\.dsh\`）里，不在插件代码里；卸载只删代码：

```
.dsh\bili-duty\config.json   （还有 state.json、B站登录凭证）
```

所以卸载 → 重装，刷视频的设置、每天刷了几轮、B站登录状态 都还在。

三件小事提醒：

- **别用「重装 DSH」来更新插件** —— 那是两件事，重装可能动到 profile。
- **新版本新加的设置项**会用默认值（以前没这一项），想要自己的值就再填一次。
- 设置项改名/换单位时（比如「隔几小时」→「隔几分钟」）会自动换算，不用你管。

## 设置页里有什么

| 区块 | 说明 |
|---|---|
| **什么时候自己跑** | 三档：**只手动 / 只在谷时 / 全天都跑**。「只在谷时」时会展开「中午谷时 12:00–14:00」「晚上/夜间谷时 18:00–09:00」两个勾选框；只要是自动（不是只手动），下面还有一个**两轮之间至少隔几分钟**（默认 180，最少 5、最多 720）。按这个节奏一轮一轮轮转，**跑到「每天最多自动刷几轮」用完为止**；手动跑不受间隔限制。谷时口径依据 DeepSeek 定价：工作日 9:00–12:00、14:00–18:00 是高峰，其余（**含整个周末**）都是谷时 |
| **派子代理刷的模型** | 选 provider + 模型（联动下拉，选中即存）。默认「**跟当前会话一样**」；也可以指到免费或便宜的中转，那样就不花官方额度的钱 |
| **自动刷在哪个会话** | 到点时往哪个会话里递话。**不选 = 自动挑最近聊过的那个**；连一个都没有才临时新建（用完自动释放） |
| **提示词（可改）** | **四段都能自己写，留空都 = 用内置默认**：① **子代理提示词**（派出去的子代理看；`{owner}` `{direction}` `{n}`）；② **投递提示**（报告交回时附给伙伴看，告诉它怎么发评论/私信；`{owner}` `{mention}` `{commentQuota}` `{uid}` `{commentBlock}` `{dmBlock}`）；③ **自动刷触发语**（到点塞进目标会话的那一句；`{owner}`）；④ **评论怎么写**（发公开评论时照它写；`{owner}` `{mention}` `{quota}` `{style}` —— `{style}` 每次从几种口吻里随机挑一种，省得每条都一个调门）。「称呼」改了，四段里的名字一起变 |
| **一轮挑几条** | 每次最多挑几条（1–10）。和「每天最多自动刷几轮」是两件事 |
| **挑什么样的** | 两道**硬门槛**：最低播放量、至少发布几天。不达标的视频在**搜索那一步就被滤掉**，子代理根本看不到（0 = 不过滤）；有门槛时会自动多抓几倍再筛，免得筛完一条不剩 |
| **它会不会替你说话** | 「自动评论并 @ 你」开关 + 每轮几条（0–20）+「要 @ 谁」（留空 = 不发评论）；再往下是**投递方式**：只发评论 / 只私信 / 评论+私信。另有「**允许发公开动态**」（`dynamicOn`，默认关）—— 开了才允许 `bili_send_dynamic` 在主页发动态；开了之后下面还有：**每天最多几条**（1–10，默认 3）、**两条之间至少隔几分钟**（1–720，默认 10），以及「**到点自动发**」——到点由插件把一句话派给你选的那个会话，**不绑当前对话**，每天只派一次、错过 3 小时不补，时间（默认 22:00）与会话都能在页面里选 |
| **日报写多细** | 完整 / 薄 / 不写。薄只留「值不值得 + 链接」 |
| **有人找我就马上告诉你** | 默认关。开着之后隔一会儿问一句 B站：有人私信你、@ 你、回了你的评论，就立刻把内容递到伙伴手上，不用等下一轮刷。两个子开关（**私信** / **@ 和回复**）、**间隔 60–1800 秒**、**只在谷时 / 全天** |
| **环境与账号** | 装主依赖、测一下、扫码登录 |
| **它的地盘** | 插件家目录、今天的报告、打开文件夹 |

> 设置同时落在两处：插件自己的 `config.json` 和 DSH 原生「插件设置」。
> **以设置页（DSH 原生那层）为准**——那才是真正生效的值。

## 命令行扫码登录（不想开设置页时）

设置页出码有个小麻烦：PNG 每次写到同一个文件名，容易被聊天窗口 / 看图器缓存成旧码；而码只有约 180 秒，等你看到消息再拿手机，常常已经过期。

`bin/qr.mjs` 是另做的独立程序，复用同一套登录逻辑：

- 直接**在终端里画码**（`qrcode.print_ascii`），完全不经过图片缓存
- 同时存一张**文件名唯一**的 PNG，并调系统看图器打开
- 每 0.8 秒轮询；过期自动换新；扫上并确认后把凭证写进插件家目录
- 写凭证失败（沙箱下常见 `EPERM`）会明确提示，并把凭证备份到 PNG 同目录

Windows 双击 `bin\二维码登录.cmd` 即可；其他平台 `node bin/qr.mjs`。
参数与实现细节见 [docs/二维码登录.md](docs/二维码登录.md)。

## 投递方式：评论 / 私信 / 都要

- **只发评论**（默认）：在挑中的视频下面留一条很短的评论，@ 你填的那个人 —— 别人也看得到，所以只说一个点、不带私事。
- **只私信**：一条公开评论都不发，最不打扰别人。私信内容可以详细（实测 500 字符就顶，别太长）。
- **评论 + 私信**：两边都发。

⭐ **两者都开时，有一道硬闸**：这一轮**还没发评论**就发不出私信（会被顶回去让你先评论）。
因为实测模型**会习惯性跳过评论**、只顾着发私信。评论"调过就算"（失败也解锁），不会把伙伴卡死。

⚠️ B站 对「陌生人私信」会限流、可能不弹提醒 —— **建议先让两边互关**。

## 有人找我就马上告诉你

平时要等到谷时刷那一轮，才知道有没有人 @ 你、私信你 —— 中间那几个小时就干等着。
开了这个（**默认关**），它会隔一会儿问一句 B站：有新消息就立刻把「谁、说了什么、哪条视频」递到伙伴手上。

- **B站 没有推送接口**（没有 webhook、也没有回调地址），所以「马上」只能是**定时去问**。
  默认 **120 秒**问一次，最短 60 秒 —— 再勤就有被 B站 限流的风险（那边会返回 `-412` 或者让你验证）。
- **问得省**：先问一个「未读数」（一个请求、几百字节），数字变了才去读具体是谁说了什么。
  没消息的时候就是一句数字，不会把私信列表全拉一遍。
- **只在谷时 / 全天**：默认只在谷时问（高峰时段把会话叫醒比较贵）。
- **同一条只递一次**：私信记在插件家目录的 `watch.json`，@ 和回复跟「每轮顺手看一眼」共用 `inbox.json` 的账，
  两条路不会把同一件事提两遍。
- **这是通知，不是代回**：回不回、怎么回、要不要看那条视频，仍然由伙伴自己决定。
- 关着的时候**一个请求都不发**；出错会退避（隔三倍间隔再试），不会一直撞。

## 费用

- **子代理走你选的那个模型**：指到免费/便宜的中转，这一轮就不花官方额度的钱。
- **自动刷默认只在谷时触发**（也能选「全天都跑」，那就是高峰时段也花）；「每天最多自动刷几轮」填 0 = 不自动跑，只手动跑。
- **手动「现在跑一轮」不占额度**。
- ⚠️ 已知小缺陷：自动刷的额度在**触发那一刻**就 +1，那一轮失败也占额度。
- 改设置**不影响** DSH 的前缀缓存，不额外花钱。

## 红线（写死在提示词里）

- 不透露你的隐私：账号、机器路径、聊过的内容 —— 一个字都不进评论
- 公开评论**极短**、只说一个点；不带私事、不刷屏、不吵架
- 不确定的事**不编**（报告里如实写「没查到」）
- 没字幕的视频直接跳过，不硬编内容

## 装不上 / 用不顺时

1. **设置页里根本不出现「刷B站」** —— 多半是 DSH 版本不满足（静默跳过），
   或插件没重启。先确认版本，再重启一次。
2. **扫码时一直不出二维码** —— 家目录里 `pythonPath` 落成了 `python`。
   设置页点一次「装主依赖」，它会自动指回插件自己的 venv。
3. **「自动刷」没动静** —— 看 `duty.log`：如果写着「目标会话现在没醒着」，先去那个会话里说句话，让它醒着。
4. **下不动 `uv`** —— 自己放一份 `uv.exe` 到 `<家目录>\bin\`，插件会用那一份、跳过下载。
5. **想更新到新版** —— 设置页最上面的「检查更新」会给一条现成的命令，照着跑，完了重启一次 dsh。

## 如果你是一个 AI 助手，正在帮用户装这个插件

1. 先确认机器上有 `Python 3.10+` 或 `uv`（`python --version` / `uv --version`）；都没有就先装 `uv`。
2. 装插件：`dsh plugin --profile desktop add github:Yuuyuko-uu/dsh-bili-subagent`。
3. ⚠️ **提醒用户重启一次 dsh**，不重启插件不生效。
4. 重启后进 **设置 → 刷B站**：先「装主依赖」，再「扫码登录」（确认时选「记住我 / 长期」）。
5. **不要**替用户开「自动评论并 @ 你」——那是拿用户的号公开说话。要用也得用户自己填「要 @ 谁」。

## 开发者离线预检

Node.js 22+ 下，在仓库里运行 `npm run selfcheck`（或 `node selfcheck.mjs`），回归测试运行 `npm test`。
不需要 `tools/register.mjs` 或自定义 loader：`index.js` 已通过 `lib/hostdeps.mjs` 解析宿主/本地依赖，
缺包时使用现有回退路径；无需先安装依赖也能检查这条降级路径。

预检在假 ctx 和假 DOM 上实际加载 host/client 并执行挂载，每次创建独立的临时家目录，成功或失败退出都会清理。
它不执行已注册工具，不启动 Python MCP、不调用模型或 B站接口。PASS 只表示这套模拟挂载通过；
不代表缺失宿主包时也验证了真实宿主的 schema、浏览器渲染、登录或社交功能。
